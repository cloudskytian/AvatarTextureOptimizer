# AvatarTextureOptimizer（ATO）

> 适用于 VRChat Avatar 的开源 **NDMF** 工具：分析 Avatar 网格上材质引用的贴图，建立「网格 UV ↔ 贴图」映射，
> 按**感知质量算法**缩放 UV 岛、剔除未使用的贴图区域、重新分配 UV，并尽可能把多张贴图重组合并成
> 一个或多个**图集**，在保证质量的同时最大化贴图利用率、显著降低显存与内存占用。

- 包名：`net.fosa.avatar-texture-optimizer`
- 运行时机：NDMF `Optimizing` 阶段（**Modular Avatar 之后、Avatar Optimizer 之前**）
- 兼容：VRChat SDK3 Avatar、NDMF ≥ 1.4、Modular Avatar、Avatar Optimizer（UV 兼容 API）、lilToon 及任意使用标准着色器属性的 shader
- 许可证：MIT

---

## 快速开始（小白向）

1. 用 VPM（或手动）安装本包及其依赖：`com.vrchat.avatars`、`nadena.dev.ndmf`、`nadena.dev.modular-avatar`。
2. 选中你的 Avatar **根对象**（挂有 `VRC_AvatarDescriptor` 的那个），
   菜单 `Component → Avatar Texture Optimizer → Avatar Texture Optimizer` 添加组件。
   > 一个 Avatar（含子物体）只允许挂载 **一个** ATO 组件；挂载对象上必须存在 `VRC_AvatarDescriptor`，
   > 否则烘焙会报错中止。
3. 默认设置即可直接使用（平衡质量挡位、自动生成图集、自动压缩、自动 MipStreaming）。
4. 点击 Inspector 里的 **「立即烘焙」**，或直接上传 Avatar —— 构建时会显示进度并可随时取消。
5. 烘焙完成后，NDMF 控制台会输出 `[ATO]` 开头的**报告**（总体结果 + 可过滤的细节：每步耗时、
   图集尺寸/利用率/贴图来源、处理岛数、像素削减量等）。
6. 上传后 Avatar 表现应保持不变；若个别素材出现异常，把它加进**白名单**即可完全跳过优化。

## 它做了什么

1. 遍历 Avatar 全部（启用或被动画启用的）Renderer 的材质槽，跳过 `EditorOnly`。
2. 通过着色器属性表分析每张贴图的用途（主色 / 法线 / 灰度蒙版 / 其他）、UV 通道、ST 变换、
   渲染模式（Opaque/Cutout/Blend）与 Cutoff，并分析全部动画（材质切换、贴图切换、ST/渲染模式/Cutoff
   动画、物体启用、缩放动画）。
3. 只处理「经网格 UV 采样、没有任何平移/缩放/旋转（含动画）变换、非贴花/MatCap/屏幕空间等特殊用途」
   的 `Texture2D`；**任一条件不满足即视为白名单**（跳过所有优化并输出 warning）。
4. 对贴图按**实际像素 + 导入设置**去重（导入设置不同视为不同贴图）并更新引用；去重结果继承白名单。
5. 提取 UV 岛（按 UV 空间邻接合并；支持多通道 UV；越界但可整体平移到 [0,1] 的自动归一化；
   跨 wrap 缝依赖 repeat 的视为白名单并警告；同贴图内重叠岛自动合并）。
6. 按**目标质量算法**对每个 UV 岛做二分搜索缩放（先均匀、全部指标达标后再双轴独立细化），
   并使用**像素密度**（默认最小 2048 / 最大 4096 px/m，可选 512~8192）防止发糊或浪费，
   同时受岛在原贴图上真实尺寸的钳制；形态键只取 0/100 两态取大、动画缩放取最大。
7. 质量算法：
   - 线性空间重采样；透明贴图**预乘 alpha** 下采样；
   - 不透明主色：**MS-SSIM**（包围盒短边 <176px 回退单尺度 SSIM，<11px 忽略该参数）+ **ΔE2000 (CIEDE2000)**；
   - 透明主色：另加 alpha 指标 —— Cutout 用 clip 后轮廓 **IoU** / Blend 用线性 **RMSE**，
     被多个材质引用时对每个材质的渲染模式与 Cutoff 逐一评估取最严；
   - 法线贴图：正确解码 → 重采样 → 重归一化 → 编码后**角度误差 p95**；
   - 灰度/蒙版：仅在被使用通道上、线性空间 **RMSE**，逐通道取最差；
   - 缩小后的覆盖区双线性上采样回原尺寸与原图比较；评估用 **Burst 并行 + GPU(RenderTexture) 批量执行**。
   - 目标质量为 1（近无损）时跳过该类型缩放、原样拷贝；纯色岛直接短路缩到 `min(4, 原岛包围盒短边)`。
8. 装箱（开启图集时）：
   - 按**贴图类型组**装箱：同组贴图（主色+法线+蒙版等，含色彩空间与 filterMode 维度）共同生成图集，
     解决「一张大图集只有一张有法线贴图、其余 9/10 浪费」的问题；
   - **UV 组**保证同一 UV 在不同图集上的位置与尺寸完全一致（含动画切换贴图），防止错位；
   - **Burst 光栅位掩码（4px 粒度）+ 全扫描 BLF**，光栅化面积降序 + 边长降序 + 90° 旋转步进
     （位掩码转置；含法线贴图的 UV 组不旋转，法线切线数据保持原样、绝不重算）；
   - **候选图集池**：默认 2 的幂（64~8192，移动端 4096），可选实验性 **NPOT**（64 步进，自动剔除 PVRTC 等
     不支持格式）；候选按面积升序、长宽比升序（最接近正方形优先），第一个能装下全部岛的即为成品；
   - 单张贴图无法装入最大图集时放弃其整个 UV 组的图集化，转整图缩放并警告；
   - 图集 padding = `max(最小 padding(4/8/16/32/64 可调), ceil(图集最大边/128))`；
   - 空白区域用 **GPU pull-push（无限外扩）** 填充（透明贴图 alpha 保持 0）。
9. 生成图集与 fallback 贴图按 不透明主色 / 透明主色（按是否含 alpha）/ 法线 / 灰度 分类设置**安全压缩格式**
   （含 Crunch、ASTC、ETC2、PVRTC 等，平台受限选项自动剔除并兜底）；
   Mipmap 与 **MipStreaming 绑定为单一开关**（VRChat 要求），默认开启；
   图集强制 **Clamp**、默认关闭 Read/Write；所有不在白名单的贴图默认开启 MipStreaming。
10. 重写网格 UV（多通道独立处理；AAO 已安装时自动做 **UV 撤离**兼容 `UVUsageCompabilityAPI`），
    更新材质贴图引用与动画引用（材质槽索引变化同步重映射），随后按内容/参数对材质与贴图去重、
    合并相同不透明材质槽（动画未单独切换时），最终移除自身组件并输出报告。

## 质量挡位（高级选项内可改）

| 挡位 | 目标质量 | MS-SSIM | ΔE2000 | Cutout IoU | Blend RMSE | 法线 p95° | 灰度 RMSE |
|---|---|---|---|---|---|---|---|
| 近无损 | 1.00 | 1.0 | 0 | 1.0 | 0 | 0 | 0 |
| 高 | 0.98 | 0.995 | 1.5 | 0.995 | 0.005 | 1.5 | 0.010 |
| **平衡（默认）** | 0.95 | 0.98 | 3.0 | 0.98 | 0.015 | 3.0 | 0.020 |
| 性能 | 0.90 | 0.95 | 6.0 | 0.95 | 0.040 | 6.0 | 0.040 |
| 极限 | 0.85 | 0.90 | 10.0 | 0.90 | 0.080 | 10.0 | 0.080 |
| 自定义 | 默认 1.0 | 全部由用户指定（不会被其他挡位覆盖） | | | | | |

> 阈值依据感知研究：CIEDE2000 的 JND 约为 1.0~2.0（Sharma et al., 2005）；
> SSIM > 0.99 一般认为不可察觉；法线角度误差 <2° 视觉无损。全部指标达标才判定通过。

## 平台覆盖

`PC / Android / iOS` 可分别覆盖全部优化参数（质量、像素密度、压缩、Mipmap、图集选项）。
默认值读取当前构建平台；勾选对应平台才显示覆盖项。受平台限制的参数（如 PVRTC 仅 iOS、DXT/BC7 仅 PC、
移动端图集上限 4096）会自动受限并安全兜底。

## 白名单

支持任意对象类型（网格、材质、贴图、动画、GameObject、组件…）：
- 白名单对象引用到的**全部贴图**跳过所有优化（含导入参数优化）；
- 与白名单贴图**同 UV 的其他贴图**跳过图集化，但仍参与整图缩放与导入参数优化。

## 性能与安全

- GPU（RenderTexture）+ 多线程 + Burst 并行；贴图解码、光栅化、质量评估均有缓存与池化，避免重复解码。
- 烘焙/构建期间显示进度，支持**取消**（中止并释放 CPU/GPU/内存，保留磁盘上的临时资产）。
- 生成资产命名 `ATO_` 前缀，存放在 NDMF 临时目录，构建成功后自动清理。
- 质量比较分辨率上限 1024px（防内存爆炸）；异常路径均有安全 fallback（CPU 兜底、整图缩放兜底）。
- 只修改贴图引用与 UV，**绝不动材质内其他着色器参数**。

## i18n

内置英文与简体中文；语言选项自动跟随 NDMF 当前语言（Auto），缺翻译回退英文。
高级用户可在任意 `Assets/**/ATO_i18n/*.json` 目录放置自定义语言文件（`{"key":"value"}` 格式），
Inspector 里会自动出现对应语言选项。

## 开发者扩展

- 所有核心数据结构与算法均为公开类，可复用：
  `Analysis`（UV↔贴图映射/白名单/去重）、`UV`（岛提取/世界面积）、`Quality`（质量评估/缩放）、
  `Atlas`（装箱/候选池/光栅掩码）、`Processing`（写出/UV 重写/动画修补/压缩）。
- 扩展点：`ShaderAnalyzer`（自定义着色器属性表分析）、`RenderModeResolver`（渲染模式判定）、
  `i18n`（语言文件）、白名单（对象引用）。
- 构建钩子：`BuildPipeline.Execute(GameObject, ATOLogger)` 可被第三方直接调用。
- 所有日志以 `[ATO]` 开头并包含耗时；`verboseLogging` 可开详细日志。

## 已知限制

- 暂不支持 NDMF 预览（预览系统未接入）。
- 动画路径解析以 Avatar 根为基准（VRChat 标准用法）；非常规 Animator 挂载（非根对象）可能需白名单。
- 处于开发阶段：配置字段可随版本调整，不保证二进制兼容；建议每次大版本前备份 Avatar。

## 常见问题

**Q：烘焙后 Avatar 某些部位变糊 / 变色？**
A：把对应材质/贴图加入白名单即可跳过；或调高质量挡位 / 最大像素密度。

**Q：图集没生成？**
A：检查「生成图集」是否勾选；某些贴图因 ST 变换/动画/越界跨缝等原因会自动视为白名单（控制台有 `[ATO]` 警告）。

**Q：可以和其他优化工具一起用吗？**
A：可以。ATO 在 MA 之后、AAO 之前执行，并实现了 AAO 的 `UVUsageCompabilityAPI` 撤离兼容。
